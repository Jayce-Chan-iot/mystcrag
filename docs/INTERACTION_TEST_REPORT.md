## 2. 关键实现说明

### AI 候选一致性

前端使用 `Promise.allSettled` 收集三个生成请求：

- 只要至少一个候选成功，就保存并展示所有成功候选。
- 只有三个候选全部失败时才显示错误。
- 结果页标题、辅助标签和卡片数量均以实际成功数量为准。

该策略保留现有后端独立候选生成接口，同时消除了“数据库已成功、用户却只能看到整体失败”的不一致。

### 订单幂等

- `orders` 新增 nullable unique `idempotency_key`，兼容既有订单数据。
- 新订单的服务端幂等键由已验证用户、设计 ID 和 revision 共同确定。
- 顺序重试先返回同用户、同 revision 的已有订单。
- 并发首次提交通过唯一幂等键收敛为同一订单；PostgreSQL 17 集成测试验证两个并发请求只产生一条订单记录。
- 前端用经过 `CreateOrderFromDesignResponseSchema` 校验的本地记录恢复同浏览器刷新后的完成状态；服务端幂等仍是跨标签页和跨设备的最终保护。
