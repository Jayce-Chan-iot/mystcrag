# 玄圭星台：极速问卦与全站视觉重设计规格

**Integration task:** `TASK-ORACLE-PLAN-002`
**Status:** APPROVED — 用户已确认视觉方向、功能方向、极速交互与完整规格；本版本已对齐 `main` 的 `BASE-004` 冻结基线与 Authing OIDC 身份实现
**Date:** 2026-09-26

## 1. 目标

将玄矶从现有的功能型水晶手串平台升级为具有辨识度的“玄圭星台”体验，同时保留现有真实商品、定价、库存、适配、保存和下单权威链路。

本次设计包含两个不可颠倒的阶段：

1. 先修复影响信任、可用性和完成率的高优先级问题；
2. 再以“星台”视觉语言重设计全部主要用户页面，并新增与水晶设计相连的“一键三钱问卦”。

问卦不是独立算命产品。它是低摩擦的文化灵感入口，用六爻结构产生可解释的设计信号，再由现有商品目录和设计引擎生成可购买、可编辑的水晶手串。

## 2. 已批准的产品决策

- 视觉方向：更强的东方玄学氛围，主题名“玄圭星台”。
- 功能方向：`星台问卦`，与水晶选材、配色、排列和点睛珠位置相结合。
- 起卦方式：三钱法，不采用耗时的蓍草交互。
- 用户操作：一次点击自动完成六次掷钱，不要求连续点击六次。
- 时间目标：不可跳过的仪式动画不超过 4 秒；问卦本身约 15 秒内可理解并进入水晶设计。
- 问题输入：可选，不输入也能起卦。
- 结果默认简洁：一句卦意、三个关键词、本卦与变卦、推荐水晶设计方向、一个主要行动。
- 详细爻辞、演算过程、文化出处折叠展示，不阻断主流程。
- 产品措辞：自我观察、文化体验和设计灵感；不得宣称确定命运、转运保证、医疗或心理治疗效果。

## 3. 体验原则

### 3.1 快于解释

用户不需要先学习六爻。首次页面只解释一句：“凝神一问，星台将以六爻为你生成一组水晶设计线索。”主要按钮直接使用“启卦”。

### 3.2 一次操作完成仪式

点击“启卦”后，系统一次性生成六次三钱结果。界面以六道星轨从下到上依次点亮爻位，总时长 2.8–4 秒。动画只是已生成结果的表现，不参与随机算法，也不得延迟服务端结果。

`prefers-reduced-motion` 用户直接使用短淡入；回访用户可关闭完整动画。

### 3.3 卦象服务于设计

结果页不把用户留在长篇占卜解释中。首屏核心行动是“以卦选石”，并清楚说明卦象只提供设计方向，实际水晶、数量、价格和库存由商品目录与设计引擎决定。

### 3.4 权威数据不被氛围覆盖

腕围、目标内周长、成串材料路径长度、适配余量、库存、价格、设计版本和订单快照继续由现有权威模块负责。星台视觉和问卦映射不得伪造或覆盖这些值。

## 4. 极速问卦流程

### 4.1 入口

首页主要创作入口按可用能力动态排列：

- AI 设计
- 星台问卦
- DIY 创作
- Tarot 仅在功能开关开启时出现；关闭时不留下空列，也不继续在 Hero 中宣传不可用功能。

### 4.2 起卦页

起卦页只保留三个必要元素：

1. 可选的一句话问题；
2. 可选腕围，优先沿用已保存偏好；
3. “启卦”主按钮。

文化说明、隐私说明和算法出处放入次级抽屉。输入问题不是启卦前置条件。

### 4.3 自动掷钱

一次点击触发一个带幂等键的创建请求。服务端使用加密安全随机源生成六组独立的三钱结果，并按自下而上的顺序得到六爻。

每枚钱使用两种等概率结果，映射为 2 或 3；三枚相加得到：

| 和值 | 爻态 | 概率 |
| --- | --- | --- |
| 6 | 老阴，动爻 | 1/8 |
| 7 | 少阳，静爻 | 3/8 |
| 8 | 少阴，静爻 | 3/8 |
| 9 | 老阳，动爻 | 1/8 |

引擎由六爻推出本卦、动爻索引、上下卦与变卦。算法版本和六次结果进入可审计记录；动画状态不进入领域记录。

### 4.4 结果页

默认首屏只展示：

- 一句话设计导向，不写确定性预言；
- 本卦 → 变卦；没有动爻时只展示本卦；
- 三个观察关键词；
- 主色、辅色、材质节奏与点睛珠建议；
- “生成我的手串”主按钮；
- “查看卦象详情”次级入口。

页面在短动画期间自动预取水晶候选。推荐尚未完成时，卦象结果先可读，候选区显示稳定骨架，不让用户等待空白页。

### 4.5 进入设计

首发沿用现有三方案比较能力：平衡、对照、中性引导三种候选均来自同一卦象设计信号，但必须使用真实目录 SKU、权威价格、库存和现有适配规则。用户选择后进入同一 2.5D DIY 编辑器继续调整。

## 5. 卦象与水晶的映射边界

### 5.1 纯问卦引擎

新增候选包 `@mystcrag/oracle-engine`，作为纯 TypeScript 领域模块。它不导入 React、DOM、数据库、AI 提示词、商品目录或定价代码。

核心输出只包含结构事实，并命名为引擎私有领域类型 `OracleCastDomain`：

- 六个自下而上的爻值 `6 | 7 | 8 | 9`；
- 本卦编号与上下卦；
- 动爻位置；
- 变卦编号；
- 阴阳数量和比例；
- 算法名、算法版本与随机结果记录。

引擎不输出吉凶、性格诊断、水晶功效或商品 ID。Design Contract 的公开传输类型命名为 `OracleCastDto`；Backend 是唯一允许将 `OracleCastDomain` 校验/投影为 `OracleCastDto` 的生产适配边界，消费者不得使用含混的第二个 `OracleCast` 名称。

### 5.2 设计信号适配器

版本化映射接收 Design Contract 的 `OracleCastDto`，并将卦象结构转换为共享的 `OracleDesignSignal`：

- 上卦与下卦 → 主色域、辅色域和材质气质；
- 阴阳比例 → 排列疏密、对称程度与明暗节奏；
- 动爻位置 → 点睛珠或配件的候选位置；
- 动爻数量 → 视觉对比强度；
- 变卦 → 备选配色方向，而非未来预测。

八卦、五行、色彩与材质的对应存在不同文化流派，因此对应表必须带版本、来源和文化说明，归属于知识/设计规则层，而不是硬编码在问卦数学引擎中。

### 5.3 设计引擎与商品权威

`OracleDesignSignal` 进入既有 Context Resolver / Design Engine 管线。最终产品选择仍必须遵守：

- 活跃目录和真实 SKU；
- 当前币种和权威价格；
- 库存与补货策略；
- 腕围、目标内周长和 Bracelet Engine 几何；
- `DesignV1`、修订、隐私和合规规则。

如果新增 `ORACLE_GUIDED` 设计模式，必须先由 Design Contract 任务增加唯一共享枚举与 provenance 结构，消费者不得自行重复声明。

## 6. 内容与开源参考策略

### 6.1 采用策略

不整包接入某个开源占卜应用。采用“公开算法 + 独立实现 + 对照测试 + 来源清单”的方式，减少依赖、许可和内容版权风险。

| 参考项目 | 许可证/状态 | 采用范围 |
| --- | --- | --- |
| [limjiechao/ts-hexagram-generator](https://github.com/limjiechao/ts-hexagram-generator) | MIT；活跃；内部包未作为稳定公开依赖发布 | 参考纯领域模型、六爻类型和演算记录，不整包依赖 |
| [Brianfit/I-Ching](https://github.com/Brianfit/I-Ching) | MIT；较旧 | 作为三钱/蓍草概率和结果的独立测试参照，不作为运行时依赖 |
| [pro-vi/iching](https://github.com/pro-vi/iching) | MIT；活跃 | 参考“观察而非预测”、私密记录和追加式札记理念 |
| [DaviRain-Su/classic_system](https://github.com/DaviRain-Su/classic_system) | 代码 MIT；部分现代内容 CC BY-SA 4.0 | 仅参考卦象矩阵与可视化信息结构；不复制其现代释文 |
| [6tail/lunar-javascript](https://github.com/6tail/lunar-javascript) | MIT；成熟 | 首发不需要；未来仅可通过窄适配器提供节气氛围，不接入吉凶输出 |

### 6.2 文本版权

- 卦名、卦象和明确处于公版的古典中文可在记录来源后使用。
- 不复制仍受版权保护的现代译文、注解或商业占卜内容。
- 玄矶的一句话卦意、关键词和水晶设计释义必须原创，并接受合规审查。
- 若参考带 ShareAlike 条款的现代内容，不得混入闭源产品文案，除非产品所有者明确接受相应许可义务。
- 依赖或复制任何 MIT 代码前，必须在依赖/许可清单保留版权声明和具体来源。

### 6.3 内容语气

允许：“此卦可作为你观察当前节奏的一个角度”“设计采用沉静主色与一颗转折点睛珠”。

禁止：“你一定会发财”“佩戴后治愈焦虑”“此卦证明某人会回来”“水晶可以改变命运”。

## 7. 隐私与持久化

### 7.1 默认策略

- 问题可选，且默认不保存。
- 首发可以只持久化卦象、算法版本、设计信号、候选设计关联和用户选择，不持久化原始问题。
- 原始问题不得进入普通请求日志、公开 DTO、设计故事、社区内容或 AI 提示词。
- 后续若支持“保存问题”，必须显式选择、独立加密并更新安全规范；不得以明文或自制可逆编码保存。

### 7.2 会话模型

建议生命周期为：

```text
CAST -> RECOMMENDED -> SAVED
```

没有需要用户逐步操作的 `DRAWING` 状态。创建请求原子地产生完整六爻。推荐失败不会破坏已完成的卦象；用户可重试推荐，而不能在原会话中重新随机。重新起卦必须创建子会话并保留来源关系。

所有会话和候选设计均按已验证用户隔离。刷新后可以恢复服务端权威状态；客户端不得自行宣称保存、价格或修订成功。

## 8. API 与契约方向

最终字段由 contract-first 实施任务冻结。本规格批准以下边界：

### `POST /api/oracle/sessions`

创建并完成一次问卦。接受操作幂等键、可选腕围和默认不保存的可选问题。返回公开安全的六爻、本卦、动爻、变卦、展示关键词、设计信号摘要和会话修订。

### `POST /api/oracle/sessions/:id/recommendations`

使用已持久化卦象生成三套真实目录候选。精确重试必须幂等；目录、价格或定价版本变化时按现有权威规则重新验证，不得复用陈旧候选。

### `GET /api/oracle/sessions/:id`

恢复当前用户自己的公开会话投影。不同所有者与不存在的资源在 HTTP 边界保持一致的安全错误策略。

### `POST /api/oracle/sessions/:id/save`

记录用户选择的设计关联，并进入 `SAVED`。设计本身仍由现有 Design Save API 持有修订和保存权威。

## 9. 玄圭星台视觉系统

### 9.1 视觉语言

- 基底：黑曜石、墨黑漆面、深靛夜空；
- 内容面：暖玄纸与低饱和骨白；
- 金属：旧黄铜，不使用高亮电商金；
- 宝石强调：紫水晶与月银；
- 图形：宋代星图、浑仪、玉璧、刻度、细金属镌线；
- 质感：克制、留白、精密、静谧；避免霓虹、玻璃拟态、廉价粒子和泛滥发光。

### 9.2 字体与密度

标题可以使用具有东方书卷气的展示字体，正文、数字、价格和操作仍使用高可读字体。正文不得用 9–11 px 承担关键信息；移动端交互目标至少 44 px。装饰字距不能牺牲中文可读性。

### 9.3 动效

动效表现“仪器校准”和“星轨显现”，而不是魔法爆炸。使用短路径、低频、可中止的 transform/opacity 动画；支持 reduced motion。问卦核心动画不超过 4 秒，页面过渡通常为 160–360 ms。

### 9.4 组件原则

共享组件进入 `packages/ui`：星台按钮、刻度分隔、纸面/漆面容器、状态徽记、卦线、仪器式进度与空状态。页面编排留在前端应用。装饰层使用 `pointer-events: none`，不能阻挡点击和键盘导航。

## 10. 全部主要页面范围

重设计覆盖：

- 首页与全局导航；
- AI 问卷、生成中、三方案结果；
- 星台问卦的起卦、短动画、结果与详情；
- Tarot 设置、抽牌、揭示、结果，但仅在功能开启时出现；
- 2.5D DIY 工作台；
- 水晶资料库、筛选与详情；
- 灵感画廊、设计详情与公开/私密状态；
- 个人中心、设计记录、订单记录；
- 登录相关壳层（复用已冻结的 Authing OIDC / desktop-recovery 会话与 `AuthRequiredDialog`，不改变身份契约）；
- 加载、错误、空状态、离线恢复和 404；
- 移动端底部导航和桌面导航。

知识后台只同步基础设计 token、排版和状态组件，不承担沉浸式星台叙事。实验性 3D 不因本次视觉改造升级为生产主路径。

## 11. Phase 0：重设计前必须修复的问题

以下问题先修复并通过回归，随后才进入大面积视觉重构：

1. Tarot 关闭时首页留下空白第三列，Hero 仍宣传不可用 Tarot；
2. `/#inspiration`、DIY 的搭配推荐/历史方案/收藏等无行为入口，以及不能真正重试的重试按钮；
3. 腕围、材料路径长度、推荐内径混在一起，用户无法判断当前是否合适；
4. DIY 桌面信息重复、目录/网格/货架同时竞争注意力，短视口右栏主按钮被裁切；
5. 错误通知覆盖工作台控制，运行时错误叠层需要清零或明确隔离开发警告；
6. 关键文字过小、低对比，部分触控目标小于 44 px；
7. 加载、失败、空状态和不可用功能不能以空白区域或死按钮代替。

适配信息统一为“佩戴适配”模块，至少明确区分：

- 用户腕围；
- 目标内周长；
- 当前成串材料路径长度；
- 弹力/结构余量；
- 当前差值与可执行调整建议。

## 12. 实施顺序与任务拆分原则

本规格批准方向，不授权跨模块直接开工。后续计划必须按仓库治理拆成互不重叠的注册任务：

1. Phase 0 前端修复与回归；
2. Design Contract 的 `ORACLE_GUIDED`、DTO 和 provenance；
3. 纯 `oracle-engine` 与概率/属性测试；
4. Context Resolver 的版本化卦象映射；
5. AI Agent 的原创、合规安全文案；
6. 数据库、仓储、Backend API、幂等和隐私；
7. 前端问卦流程与恢复；
8. 共享星台 token/组件；
9. 按页面族逐批重设计，避免一次性改动全部路由；
10. 跨工作区、浏览器、移动端、可访问性和视觉回归 QA；
11. 文档、特性注册、依赖许可与发布开关。

共享契约先于消费者；数据库、API、AI/设计规则、Bracelet 或 3D 契约发生变化时必须同步更新对应控制文档。

## 13. 错误与恢复

- 双击“启卦”只能创建一个会话；按钮在请求期间显示明确状态。
- 网络失败保留用户可选问题在当前内存中，并提供真实重试；不得伪造卦象。
- 已成功起卦但推荐失败时，卦象仍可阅读，并只重试推荐阶段。
- 刷新从 `GET` 恢复服务端结果；不能因刷新重新随机。
- 目录、库存或价格冲突沿用稳定错误码和权威刷新策略。
- 保存状态由服务端返回确认，重复保存不能生成重复设计或订单。

## 14. 可访问性与响应式要求

- 所有主操作可用键盘完成，焦点顺序与视觉顺序一致；
- 卦线不能只用颜色区分，必须有实线/断线和文本名称；
- 动爻同时使用符号和可读标签；
- 状态提示使用 `aria-live`，但逐帧动画不连续播报；
- 关键信息满足 WCAG AA 对比度；
- 移动端触控目标至少 44 px；
- 320 px 宽度不横向溢出，1440×560 短视口仍能看到主要行动；
- reduced motion 下没有强制旋转、视差或超过必要时长的仪式动画。

## 15. 验收标准

### 问卦核心

- 从页面加载完成到提交问卦只需一次主要点击；问题输入可跳过；
- 六爻由六组独立三钱结果自下而上生成；
- 单元与统计测试覆盖 6/7/8/9、动爻、变卦、八卦/六十四卦查表和预期概率分布；
- 同一已创建会话刷新和重试得到相同卦象，不重新随机；
- 不可跳过动画不超过 4 秒，reduced motion 有替代方案；回访用户可以关闭完整仪式动画且偏好不包含问题文本；
- 结果首屏不出现确定性命运、医疗、保证功效或心理诊断措辞；自动禁词覆盖“转运、招财、发财、保平安、辟邪、开光、加持、治愈、疗愈、旺、桃花、挽回、命定、注定、一定、必定、大师”等高频违规表达。

### 水晶设计

- 卦象到设计信号的映射有独立版本和测试；
- 三套候选使用真实 SKU、权威价格、库存和现有适配规则；
- 进入 DIY 后维持 `componentId`、顺序、价格、修订和保存语义；
- 问卦视觉状态不得改变 `DesignV1` 或 Bracelet Engine 几何事实；
- 若新增 `ORACLE_GUIDED`，枚举和 provenance 只有一个共享定义源。

### 内容、隐私和许可

- 每段古典原文有来源与公版依据；现代解释均为原创或具备兼容许可；
- 没有从 CC BY-SA 或版权不明项目复制现代释文；
- 默认不保存原始问题，日志、公开 DTO、社区和提示词中不存在原文；
- 所有采用的第三方代码/依赖进入许可清单并保留必需声明。

### Phase 0 与全站 UI

- Tarot 关闭时无空卡、无失效宣传；
- 已列出的死按钮都有真实行为、禁用说明或被移除；
- “佩戴适配”不再混淆不同尺寸概念；
- DIY 在桌面、短视口和移动端不裁切主要行动；
- 主要文本、对比度、44 px 触控、键盘和错误恢复通过回归；
- 全部列入范围的主要页面使用同一星台 token 与组件体系；
- 星台生成资产通过原尺寸人工目检，拒绝伪汉字、符箓式乱纹、西式神秘学符号、医疗符号和水晶功效暗示，并按 QA evidence policy 保存验收记录；
- `pnpm validate`、相关包测试、架构测试和浏览器主链路全部通过。

## 16. 首发非目标

- 不做八字、紫微斗数、姓名学或完整命理系统；
- 不做实时真人占卜、付费解卦或社交问卦广场；
- 不让生成式 AI 决定随机卦象；
- 不将节气、方位或时辰作为吉凶判定；
- 不直接接入外部开源应用的数据库或现代释文；
- 不在首发实现多种起卦方式；
- 不改变支付、物流、生产和库存权威；
- 不把实验性 3D 变为主编辑器。

## 17. 设计结论

玄圭星台的差异化不来自更复杂的算命步骤，而来自“极短仪式 + 可解释卦象 + 真实水晶设计”的连续体验。首发用一次点击完成三钱六爻，将复杂文化信息收进详情，把用户尽快带回选石、编辑和完成手串的核心价值。
