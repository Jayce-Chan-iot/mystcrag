## 1. 产品目标与授权范围

玄矶先以中国大陆商户主体经营面向中国大陆与台湾地区的自营精选独立站。首个合作品牌为无野设计：展示经过品牌确认的成熟成品，以及无野主理人为玄矶设计的独家系列；继续提供现有 AI、DIY、知识库、塔罗与星台问卦体验。长期可扩展其他独立设计师，但本阶段不是多商户、多租户平台。

产品所有者已说明获得无野主理人合作授权。这是开展内容准备的前提，不等于已在仓库中存在每张商品图片、每个作品版本、修改范围、展示区域和期限的可核验授权记录。公开商品上线前必须逐项关联经确认的授权与素材来源；不据此推断可任意修改或复制设计师原款。

支付服务商尚未选定，也不在当前申请范围。本阶段建成可信的商品、设计师、系列展示与个性化创作衔接；不呈现假的购物车、结算、支付成功、物流或已可购买状态。购买动作由后续独立商业订单与支付规格审批后启用。白牌、微信小程序、生产 3D、支付申请和生产部署同样后置。

已有[玄圭星台中文规格](2026-10-03-star-platform-ux-remediation-design.md)与[两模型执行计划](../plans/2026-10-03-star-execution-dispatch.md)仍控制它们列出的未完成 UX 任务。本文件只为商业展示新增页面、排版对标和跨页面连接设边界，不重新定义首珠创建、三语投影、Oracle 随机/幂等、Bracelet Engine 或生产 DIY 渲染器。两个计划发生页面路径重叠时，先完成并验收已登记任务，再为商业页面或导航登记后续单 owner 任务；不能并发编辑锁定路径。

## 3. 体验结构与页面排版

### 3.1 统一视觉语言，按场景选择版式

采用“同一视觉系统、三种页面节奏”，而非把全站套进同一张米色卡片网格。品牌应呈现克制、整洁、精密的东方当代珠宝感：清晰的深浅关系、真实商品摄影、少量金属细节、可读字体与有目的的留白。留白是为作品和信息服务，首页不得重现突兀的图片上下空带；避免脏乱石纹、密集星轨、廉价渐变、过多圆框与常驻动画。塔罗与星台各有可辨识入口，不让品牌叙事只剩占卜。

| 页面模式 | 页面与首屏任务 | 排版原则 |
| --- | --- | --- |
| **品牌叙事 / Persuade** | 首页、合作系列、设计师主页；让访客知道玄矶卖什么、与谁共创、如何开始 | 作品主图先建立焦点，短标题与一个主要动作紧随；下一内容区在首屏末端可被发现。系列/设计师段落交替使用作品图、人物/工艺证据和简短文字，不堆叠同尺寸卡片。 |
| **商品判断 / Read + Decide** | 成品目录、商品详情；让访客比较作品并看清材料、尺寸、作者与可获得性 | 列表以图片为主，筛选/排序可见而不占满首屏；详情先展示真实多角度图、名称、设计师、材料/规格与明确的展示价格/区域，再展开故事、养护与授权允许的定制入口。展示价格不暗示已可在线结算。 |
| **任务操作 / Operate** | DIY、AI、Oracle、Tarot；让访客顺畅创作并理解结果 | 保留已批准的 DIY 桌面左材料库—中托盘—右检查区、手机上托盘—下材料面板。问卦/塔罗结果先给白话方向、真实石材与下一步。此类页面不照搬大图商城布局，不牺牲操作密度和可访问性。 |

所有新页面使用同一语义 token、响应式断点体系与页眉语言入口。桌面与手机均要验证导航、首屏焦点、图片裁切、内容宽度、长文案、焦点顺序和主动作位置；至少覆盖 320×568、390×844、768×1024、1440×900、1440×560 和 200% 缩放。三语最长文本不遮挡图片、价格或按钮。触控目标至少 44×44 px，正文/交互对比符合 WCAG AA；动效只帮助层次显现，`prefers-reduced-motion` 直接给出稳定终态。

### 3.2 第一阶段页面与真实动作

1. **首页：** 顶层明确“精选设计师作品”与“自己创作”两条真实路径；无野独家系列和成熟成品用真实作品图进入目录/系列，AI、DIY、塔罗、星台仍保持清楚入口。故事与作品不混写为神秘功效。
2. **精选目录：** 仅列已审核、获展示授权、资料齐全的成品和独家系列。提供品类/设计师/系列筛选及可解释的缺货、暂未开放、空结果状态；不会混入 DIY 散珠 SKU。
3. **商品详情：** 作品图、名称、品牌/设计师、系列、材质、规格、价格币种、可展示区域、库存/咨询状态由服务端发布版本提供。可定制时只展示明确被授权的修改范围及进入 DIY 的路径；不可定制原款不出现“自由改款”。未开通购买时不出现“加入购物车”“立即支付”。
4. **设计师主页与合作系列：** 先呈现作者身份与经确认的合作关系，再呈现作品集合和创作说明；可从原款进入允许的衍生设计，但原款、衍生版本和消费者私有设计在文案与数据上保持可区分。
5. **现有创作页：** 按星台既定计划继续修复与重设计，不因商城导航改动而失去原入口、历史恢复、权限和真实材料/报价权威。

## 5. OSS-first 商业领域边界（Medusa 已选定，运行时未接入）

采用单一玄矶经营主体、多个可署名合作品牌/设计师的**策展目录**，而非现在就建立租户。下图只是业务概念，不是新增 Prisma 表、Fastify 路由或与开源内核并行的实体清单：

```text
合作品牌 Brand ── 设计师 Designer ── 合作系列 Collection
                                  └─ 作品原款 Product ── 可展示/可售规格 Variant
                                       ├─ 区域/语言/价格/状态 Listing
                                       └─ 授权范围 LicenseGrant
消费者设计 Design ──不可变 DesignRevision ──(被许可的衍生来源)── Product/Variant
```

- `Brand` 与 `Designer` 是来源与署名，不是商户账户、租户或收款方；图中的连线表示合作归属，不预设一位设计师只能合作一个品牌。玄矶仍统一负责网站经营和客户服务。
- `Product` 表达成品或明确授权的独家原款；`Variant` 表达真实规格/SKU；区域发布与**人工确认的**币种价格优先映射候选内核现有商品、价格、区域/渠道能力；`Listing` 仅为概念，不预设自建同名表。成品商业权威不得替代已有 `MaterialProduct`、`AccessoryProduct` 的逐珠材料权威。若将来有 DIY 材料包，先定义真实组合、供货与授权，不由前端拼装成“可购买”。
- `LicenseGrant` 至少能够回答作品归属、可展示素材、销售区域、是否允许消费者调整、允许调整的部位与使用期限；未获确认时默认不可发布、不可改款。具体法律文本与权限由业务方提供，本系统只存经批准的结构化引用与版本。
- `DesignTemplate` 目前没有授权和商品版本能力，不能直接升级为设计师原款权威。未来可作为展示/创作起点的内容投影，但原款与消费者修订关系应由新增商业合同先明确定义；不得回写或抹平旧 `DesignRevision`。
- 成品购买、定制订单、退款、库存预留、物流与支付在后续统一订单规格中设计。当前订单模型关联设计修订且只覆盖设计快照，不得直接复用为“已完成商城交易”。

**先复用后扩展：** 商品、规格、系列、区域定价、库存、管理界面与未来订单/履约属于成熟电商内核的默认复用范围；品牌/设计师署名、作品授权版本、媒体来源和“缺资料不公开”闸门才是玄矶特有的最小扩展候选。复用优先不等于整体迁移现有设计、材料或订单，也不等于同时拥有两套成品商品权威。任何 Fastify 公开投影、同步表或新 Prisma 实体都必须在选型后证明为何现成 API/扩展点不能满足，并写明唯一数据权威、同步/撤回、失败关闭和退出方案。

**选型结论：** `TASK-COMMERCE-OSS-FIT-001@97428aa` 的隔离 PoC 验证了 Medusa `2.21.2` 的商品/规格/系列、双市场人工区域价、三语读取与发布撤回；产品所有者于 2026-10-11 选择 Medusa。Vendure 与 Saleor 保留为评估过的备选，不并行集成。PoC 同时证实 Medusa 的缺译回退、缺价格可见、缺图片可见以及缺少授权概念，故 **Medusa 原生 Store API 不能直接作为玄矶公众页面的发布权威**；唯一公开路径必须经过玄矶最薄的服务端授权/审校/媒体/市场价闸门。具体来源、失败项与未证实项见该任务报告；依赖和隔离边界见 [`DEC-COMMERCE-001`](../../DEPENDENCY_DECISIONS.md)。

选型已获批准，但公开商品 DTO、最薄发布闸门、路由及 Medusa 部署/数据库边界仍须按 Phase 1 计划先行冻结并验证；在合同与任务登记批准前，不新增成品 Prisma 表/迁移、不自建商品/价格/订单权威，也不派发依赖未冻结接口的前端页面。公开输出始终不得泄露成本、草稿、未授权媒体或私人设计；管理员发布动作须有授权、审计与撤回路径。

## 6. 大陆、台湾与三语展示

`zh-CN`、`zh-TW`、`en-US` 仍是**语言**，不是收货区域或币种开关。大陆与台湾的可展示商品、商品文案、运送/服务说明和价格分别由经审核的 Listing 决定；没有确认的 TWD 报价不能根据 CNY 自动换算，也不能把 CNY 数字伪装成新台币。缺少某地区授权或商品资料时，该地区不发布该 Listing；不通过前端隐藏来代替服务端发布约束。

公开页面需要稳定可索引的商品/系列/设计师 URL、按语言审校的标题/摘要、规范链接与图片替代文本。具体 URL 语言前缀、缓存及区域选择机制应在 Contract/前端任务前冻结，不得在页面中分别发明。动态商品内容必须有人审校的简繁英文版本或明确保持不公开；不得机器翻译工艺、功效、授权或服务承诺。现有问卦/塔罗文案继续遵守文化体验而非确定命运或医疗效果的界限。

## 7. 依赖、任务拆分与验收门槛

本规格不是实施计划。产品所有者批准后另用 `superpowers:writing-plans` 拆成登记任务；下列顺序是设计约束，不预占路径锁：

1. **SOL：** 对照最新 `main`、活跃任务和星台执行计划登记不重叠的 OSS 选型与页面对标任务；独立审查证据并请产品所有者批准单一商业内核或有证据的最小例外。
2. **DeepSeek V4.1 Flash：** 先完成开源电商适配矩阵与隔离 PoC；仅在选型获批后按所选内核的现有 API/扩展点设计最小 Contract、授权发布闸门和集成边界，不预设自建商品表、订单或 Fastify CRUD。
3. **Qwen 3.8 Flash：** 可独立完成真实竞品/优秀独立站与开源店面排版对标、桌面/手机视觉方向；产品所有者确认后且公开接口冻结，再按页面族实现首页、目录、详情、设计师与系列页。继续完成星台计划里的未完成任务，不并发抢写共享 CSS/导航。
4. **独立 QA 与 SOL 复核：** 真实浏览器验证两市场、授权/撤回/缺资料不公开、三语、价格来源、原有 AI/DIY/Oracle/Tarot、移动端与可访问性；任何失败退回原 owner 精确复修。

每个实现任务至少提交：当前代码路径、对标卡、红绿测试、精确 diff、授权/许可审查（如适用）、目标视口前后截图、模块窄测、架构测试和 `pnpm validate` 的真实结果。整站最终视觉由产品所有者确认；规格批准、单任务代码合并和网站可上线是三个不同门槛，不能互相代替。

## 8. 明确不采用的捷径

- 不整体搬入 Shopify/Medusa 店面模板只为得到商城外观；也不跳过成熟内核选型去自建一套商品、价格、库存、订单权威。
- 不复制竞品的作品摄影、文案、品牌式样或未经核准的开源素材。
- 不把矿石文化寓意写成保健、保证转运或确定性占卜结果。
- 不用隐藏购买按钮之外的假结算、假订单或假售后流程暗示商业闭环已经完成。
- 不为新展示页重写已批准的 DIY 桌面/手机排版、实验性 3D 生命周期或现有三语/鉴权机制。
