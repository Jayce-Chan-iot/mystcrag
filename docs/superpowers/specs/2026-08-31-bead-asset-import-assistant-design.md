# 珠子素材入库助手设计规范

**状态：** APPROVED FOR PLANNING

**任务：** TASK-ASSET-IMPORT-001

**负责人：** SOL

**产品决策日期：** 2026-08-31

**目标形态：** 本地优先，保留线上多人后台的升级边界

## 1. 背景

当前珠子图片以拍摄文件夹形式交付，包含 ARW 原片和 JPG 预览图。文件夹编号只表示拍摄顺序，不是珠种、SKU 或库存批次。当前交付样本为 26 个编号目录、127 个文件（65 JPG，62 ARW），约 1.4 GiB。现有仓库已有珠子商品库 Excel 模板、Prisma 商品目录和前端静态珠子映射，但没有从本地文件夹到待审核商品的正式流程。

该功能建立一个独立的「珠子素材入库」管理入口，让操作者拖入整个文件夹，修正系统建议的相似图片分组，为每组输入珠子名称，然后生成可审核的保真扣图和商品草稿。草稿不会自动上架、不会进入 AI 推荐，也不会更改正式库存。

## 2. 已批准的产品决策

- 首版在本地运行，接口保留未来替换为对象存储和后台队列的能力。
- 管理后台提供一级独立入口 `/admin/bead-import`，与知识库后台并列，不嵌入 `/admin/knowledge`。
- 文件夹只是拍摄顺序。系统按图片相似度建议分组，人工可合并、拆分和移动图片。
- 每组只需输入珠子名称就能保存「素材草稿」。正式发布前再补齐几何、品质来源、价格、库存和权限字段。
- 图片处理为保真模式：去背景、白平衡、曝光、降噪、轻度锐化和等比裁切；禁止生成新纹理、修改真实颜色或将低清图伪装为真实高清图。
- 原始 ARW/JPG 复制到 Git 仓库之外的受管本地档案库，校验哈希后记录。不删除操作者拖入的源文件。
- 所有处理结果先进入待审核区，审核通过后才能事务性发布到正式商品目录。

## 3. 目标与非目标

### 3.1 目标

1. 将一批本地拍摄文件可恢复、可追溯地归档。
2. 自动检测 ARW/JPG 配对、精确重复和近似连拍图。
3. 给出相似图片分组建议，但将商品身份和品质判断留给人工。
4. 从高分辨率 JPG 生成可用于 DIY 和商品展示的透明 WebP。
5. 保存仅有名称的素材草稿，并在资料完整后安全发布为正式 SKU。
6. 让本地文件系统、图片处理器和任务调度都能以适配器替换，不重写审核页和业务流程。

### 3.2 首版非目标

- 不根据照片自动鉴定矿物名称、天然程度、处理方式或商业品质。
- 不使用生成式模型填充珠子纹理、包裹体、高光或颜色。
- 不在拖入后直接上架、改库存或加入 AI 推荐。
- 不将 ARW、全尺寸 JPG、临时切图或模型缓存提交到 Git。
- 不做供应商 Excel 自动对账、批量改价或采购流程。
- 不在未完成生产身份系统前开放公网管理操作。

## 4. 管理员用户流程

### 4.1 独立入口

管理导航和管理首页提供「珠子素材入库」一级入口，直达 `/admin/bead-import`。该入口与知识管理并列，拥有自己的鉴权守卫、任务列表和审核队列。普通产品导航不显示该入口。

入口页显示：

- 新建导入；
- 上传中和处理中的任务；
- 待命名、待处理、待审核草稿；
- 已发布记录；
- 失败任务和可恢复操作；
- 本地档案库使用量和剩余空间。

### 4.2 四步导入向导

1. **拖入素材**：拖入一个或多个目录，或使用「选择文件夹」。浏览器上传保留相对路径，不向服务端暴露任意本地绝对路径。
2. **确认分组**：展示精确重复、ARW/JPG 配对异常和系统建议的相似组。操作者可拖动图片、合并、拆分、忽略和选择主图。
3. **输入名称**：每组输入一个珠子名称。系统搜索现有 `Crystal`；精确匹配由操作者选定，不自动认定同名或近似名。无匹配时建立待审核的新水晶草稿。
4. **处理与审核**：批量生成保真扣图，显示原图/成品对比、质检结果和处理版本。确认后保存素材草稿。

手机端必须无横向溢出并可查看任务/审核状态，但首版的整目录拖入和细粒度分组编辑以桌面浏览器为主。不支持目录上传的移动浏览器显示明确提示，不伪装成可用。

## 5. 系统架构

```text
Admin browser
  -> Frontend server-side admin boundary
  -> Backend bead-import API
       -> import/draft repositories
       -> job lease repository
       -> asset storage interface
  -> Asset Worker
       -> archive adapter
       -> grouping pipeline
       -> conservative image processor
       -> quality checks
  -> PostgreSQL draft records
  -> Local archive root (V1) / object storage (future)
```

### 5.1 前端管理功能

`apps/frontend` 负责管理路由、分组编辑器、名称选择、原图/处理图对比、任务状态和审核表单。浏览器不存储管理密钥，不直连 PostgreSQL，不执行图像处理，不根据文件名构造正式 SKU。

本地 V1 沿用现有管理服务端代理模式，但使用独立的素材管理密钥配置，不复用知识库管理密钥。线上版发布之前必须改为经生产身份提供方验证的管理员会话，不得把本地 API key 模式带入公网。

### 5.2 Backend 编排

`apps/backend` 是导入会话、草稿、审核和发布的业务权威，负责：

- 建立导入会话和分片/流式文件接收；
- 检查内容类型、大小限额、路径安全和操作权限；
- 提交幂等处理任务，查询状态并管理重试；
- 验证分组编辑、主图选择和人工名称；
- 确保草稿不出现在公开 catalog 查询中；
- 发布时调用数据库仓储完成一次事务。

首版使用短轮询查看任务状态，不引入 WebSocket。线上版可在不改变状态模型的前提下替换为事件通知。

### 5.3 Asset Worker 与处理契约

图像归档、相似度计算和扣图是独立 worker 责任，不在 Fastify 请求生命周期内执行。实现阶段建立独立 `apps/asset-worker` 和可测试的处理契约；不复用知识采集 worker，因为两者的权限、依赖、存储和失败语义不同。

本地版使用 PostgreSQL 任务记录和有期租约来防止重复处理。未来可用队列适配器替换任务获取，但任务 ID、幂等键、状态和重试语义保持不变。

### 5.4 存储边界

存储层对业务层只暴露 `provider` 和不可变 `storageKey`，数据库不把 `/Users/...` 绝对路径当作业务身份。本地适配器从未提交的环境配置 `MYSTCRAG_ASSET_ARCHIVE_ROOT` 读取档案根目录。任务归档建议布局为：

```text
<archive-root>/imports/<session-id>/raw/<sha256>.<ext>
<archive-root>/imports/<session-id>/processed/<asset-id>/v<version>/bead-512.webp
<archive-root>/imports/<session-id>/processed/<asset-id>/v<version>/thumb-256.webp
```

文件先写入会话级临时区，完成大小和 SHA-256 校验后原子移入档案键。只有校验成功才建立「已归档」记录。取消、失败或缺少空间时不删除用户源文件。

当前 `apps/frontend/public/beads/photographic/**` 保留为仓库管理的演示/静态回退资源。用户导入的动态商品图不通过 Git 发布，而是由资产解析边界把 `textureAssetKey` 解析为同源资产 URL；线上版将同一 key 解析为 CDN/对象存储 URL。正式实现该边界时必须同步更新资产清单和组件权威表。

## 6. 概念数据模型

本节定义语义，不直接规定 Prisma 表名。数据库任务必须在迁移前将其写入 `docs/DATABASE_SCHEMA.md`。

### 6.1 `AssetImportSession`

- 身份：`sessionId`、幂等键、操作者、创建/更新时间。
- 状态：`UPLOADING`、`GROUPING`、`LABELING`、`PROCESSING`、`REVIEW`、`APPROVED`、`FAILED`、`CANCELLED`。
- 进度：文件数、字节数、成功/失败数、当前阶段。
- 恢复：最后完成检查点、失败代码和可安全重试标记。

### 6.2 `AssetSourceFile`

- 相对来源路径、原文件名、扩展名、MIME/内容类型、字节数、尺寸和 EXIF 时间。
- SHA-256、感知哈希、存储 provider/key 和归档校验状态。
- ARW/JPG 配对关系、精确重复关系和忽略原因。
- 文件记录不因重新分组或重新处理被覆盖。

### 6.3 `BeadImageGroup`

- 分组 ID、会话 ID、成员文件和人工选定的主图。
- 系统分组分数和因素只用于建议，不构成矿物/商品结论。
- 人工名称、匹配的现有 `crystalId` 或新水晶草稿引用。
- 每次合并、拆分、移动和主图变更记录操作人和时间。

### 6.4 `ProcessedAsset`

- 源文件、分组、资产用途（`MAIN`、`SINGLE_BEAD`、`DETAIL`）和处理版本。
- 处理器/模型版本、参数、输出哈希、尺寸、存储 key 和质检结果。
- 来源、使用权限、是否真实实拍、是否可商用/公开展示和人工审核状态。
- 新版本不删除旧版本；「当前审核版本」是显式引用。

### 6.5 `CrystalDraft`

- 仅在人工输入的名称无法关联现有 `Crystal` 时建立，不由图像模型生成鉴定结论。
- 初始可仅保存建议中文名称和来源图片组，不进入知识、catalog 或推荐查询。
- 升级为正式 `Crystal` 前，必须人工补齐中/英文名、矿物学名称、颜色/视觉/风格标签、价格等级和合规说明，并通过重复检查。
- 正式 `Crystal` 不会因草稿重处理、分组调整或取消导入而被修改。

### 6.6 `MaterialProductDraft`

- 草稿可仅有分组、珠子名称和主图，此时状态为不可发布。
- 发布必填：`crystalId`、商品名、形状、直径或完整尺寸、品质表述及来源、`materialKey`、模型/纹理资产 key、币种、售价、成本、可用库存、权限确认和 AI 可用性决策。
- 草稿不复用正式 `MaterialProduct.active=false` 模拟，避免草稿字段和生命周期污染正式 catalog 语义。
- 发布通过数据库服务事务批准或引用 `Crystal`，创建 `MaterialProduct`，追加 `InventorySnapshot`，并绑定已审核资产。任一步失败整体回滚。

## 7. 分组管线

分组是「建议」而不是商品判定，按以下信号组合：

1. SHA-256 精确去重；
2. 感知哈希识别缩放、转码和近似连拍；
3. 主体区域颜色直方图和局部纹理特征；
4. 拍摄时间和原始文件序列作为弱信号；
5. 完全本地运行的图像嵌入作为可替换建议器，不输出水晶名称。

合并阈值必须偏保守。对低置信度建议，UI 显示「待确认」而不是自动合并。人工调整保存后是后续处理的唯一分组权威。

## 8. 保真图像处理

### 8.1 处理步骤

1. 读取 EXIF 方向并规范化颜色空间；
2. 使用主图 JPG 计算主体蒙版，ARW 首版只归档，不作为浏览器预览和默认处理输入；
3. 区分外部背景与珠子内部透明/高光区，保留内部亮部；
4. 去除外部背景和与背景相连的多余阴影，保留珠子本身明暗；
5. 以中性背景区作受限白平衡/曝光参考，对颜色偏移设硬性上限；
6. 执行边缘保留降噪、局部对比度和轻度锐化；
7. 等比裁切并置中，主体占画布约 80%，不将 3:2 原图拉伸为正方形；
8. 输出 512×512 透明 WebP 和 256×256 审核缩略图，记录处理版本和哈希。

「清晰度优化」仅使用真实输入像素做降噪、对比和保守插值。当珠子有效像素、对焦或运动模糊不达标时，输出「建议重拍」而不使用生成式细节。

### 8.2 自动质检

- 主体是否被裁断；
- 透明珠内部是否被误挖空；
- 边缘是否存在白边、黑边或明显锄齿；
- 处理前后的受限颜色差异；
- 主体有效分辨率和模糊分数；
- 画布占比、透明通道、文件大小和 WebP 解码；
- 在 DIY 紧凑珠串、商品卡和导出缩略图中的实际显示。

质检不通过不删除输出，而是标记问题并阻止发布。审核者可调整边缘、重新扣图、切换主图或恢复上一处理版本。

## 9. API 与任务语义

具体 DTO 在实现时由 Design Contract 任务先定义。服务边界至少覆盖：

- 建立/列出/查看/取消导入会话；
- 流式或分片上传、文件完成校验和幂等复用；
- 开始分组、查看建议、提交人工分组修订；
- 提交名称和 Crystal 匹配；
- 开始处理、查看质检、重新处理和选择当前版本；
- 保存商品草稿、完整性检查、审批发布和查看发布结果；
- 受权资产读取，且不接受任意文件系统路径。

每个可重试操作都使用幂等键。重试不得创建第二份原片、第二个处理版本或第二个 SKU，除非用户显式选择「新处理版本」或「复制为新草稿」。

## 10. 安全、权限与合规

- 只接受 JPG/JPEG、PNG、WebP 和 ARW，通过内容头和解码器检查格式，不仅信任扩展名。
- 文件数、单文件大小和会话总字节限额可配置，默认必须覆盖已知的 127 文件/1.4 GiB 验收批次。
- 所有存储 key 由服务端生成，拒绝 `..`、绝对路径、符号链接越界和同名覆盖。
- 处理器不接触数据库凭据以外的密钥，不将图片发给未批准的第三方服务。
- 实拍来源、权利人、使用权限、是否允许 AI 训练、商用和公开展示为审批前必填字段。
- 当权限为 `UNKNOWN` 或 `PROHIBITED`时，可保留本地待审核记录，但禁止发布到商品页。
- 水晶名称、品质和文化标签继续遵守现有合规边界，不因图像导入生成医疗、保证功效或确定性命理表述。

## 11. 失败恢复和可观测性

处理阶段定义明确检查点：`ARCHIVED`、`GROUPED`、`LABELED`、`PROCESSED`、`REVIEWED`、`PUBLISHED`。任务中断后从最后已验证检查点恢复。

错误至少分类为：

- 不支持/损坏的文件；
- 存储空间不足或校验失败；
- 归档或任务租约冲突；
- 主体分割失败或质量不足；
- 管理权限失效；
- 草稿字段不完整或关联不存在；
- 发布时的 SKU 冲突、库存版本冲突或数据库事务失败。

每个错误给出稳定代码、人类可读说明、可重试性和安全恢复动作。日志记录会话/文件/任务 ID，但不输出管理密钥、数据库 URL 或未经授权的完整本地路径。

## 12. 验证策略

### 12.1 单元和契约测试

- 文件类型、路径规范化、哈希去重和 ARW/JPG 配对；
- 任务状态转移、租约、幂等重试和检查点恢复；
- 分组合并/拆分不丢失文件或人工主图选择；
- 草稿完整性和正式发布事务回滚；
- 静态回退资产与动态 `textureAssetKey` 解析一致性；
- 处理管线的画布尺寸、比例、Alpha、颜色差限制和版本稳定性。

### 12.2 集成与浏览器验收

- 使用不含商业原片的合成小样本覆盖正常、重复、损坏、断点续传和失败恢复。
- PostgreSQL 真库测试证明草稿不会出现在正式 catalog，发布事务同时产生商品、库存快照和已审核资产引用。
- 1440×900 覆盖文件夹拖入、分组修正、命名、处理对比、重处理和发布。
- 390×844 覆盖独立入口、任务状态、待审核列表和不支持文件夹上传的明确提示，无横向溢出。
- 处理后图片在水晶库、DIY 素材列表、手串编辑器、设计结果和导出缩略图中使用同一材质身份。

### 12.3 业务数据验收

首版使用操作者指定的桌面素材目录做本地手工验收，但原片不进入测试夹、截图证据或 Git。当前批次的可测量门槛为：

- 127 个文件都能扫描或产生明确的文件级错误；
- 65 JPG/62 ARW 的配对和缺失情况可见；
- `ZDX01535` 即使位于不同编号目录，仍按文件 stem 建议配对；
- 精确哈希去重不误删近似连拍；
- 每组只输入名称即可保存草稿；
- 未补齐业务字段的草稿无法上架、定价、扣库存或进入 AI 推荐；
- 原文件保持不变，档案副本与源文件 SHA-256 一致。

## 13. 实施拆分与依赖顺序

该功能跨越共享 DTO、数据库、Backend、图像 worker、Frontend 和资产映射，不由一个无限可写路径的任务同时实施。计划阶段必须拆成以下有向任务：

1. **Contract 任务**：定义管理 DTO、状态、错误和资产 key 解析契约。
2. **Database 任务**：写数据库规范，建立草稿/资产/任务持久化与发布事务。
3. **Asset Worker 任务**：建立存储、归档、分组、保真处理和质检边界。
4. **Backend 任务**：建立独立管理权限、导入 API、任务编排和发布服务。
5. **Frontend 任务**：建立独立入口、四步向导、分组编辑和审核页。
6. **Asset resolver 任务**：将已审核动态资产接入水晶库、DIY、结果和导出，保留现有静态回退。
7. **QA/集成任务**：完成中断恢复、真库发布、桌面/手机浏览器和业务素材手工验收。

每个任务必须在 `docs/tasks/TASK_REGISTRY.md` 拥有自己的 ID、负责人、分支、可写路径和验收门。Contract 和 Database 任务先于消费者任务合入；Frontend、Worker 可在稳定 DTO 之后并行。

## 14. 发布与回退

- 功能使用默认关闭的管理功能开关；未配置管理鉴权或档案根目录时 fail closed。
- 数据库迁移只新增草稿、资产和任务记录，不改写现有商品和库存。
- 在资产 resolver 未开启前，现有静态图片映射仍是用户产品回退路径。
- 关闭功能不删除草稿、原片或已发布资产；已发布 SKU 继续通过稳定 asset key 访问已审核版本。
- 数据库回退、档案清理和对象删除是分离的、需审批的后续管理动作，不由普通取消或失败重试触发。

## 15. 设计验收结论

当实施满足以下条件时，「珠子素材入库助手」可从 `PLANNED` 转为 `ACTIVE`：

- 独立管理入口可达且 fail closed；
- 目录导入、归档校验、去重、配对和建议分组可恢复；
- 人工命名是 Crystal 关联的权威，图片不自动鉴定商品；
- 处理输出符合保真、版本化和质检要求；
- 草稿隔离和事务性发布由真库测试证明；
- 同一已审核资产在商品库、DIY、结果和导出中视觉一致；
- 源照片未被改写或提交到 Git，使用权限和操作审计完整；
- 窄范围检查、相关模块测试、PostgreSQL 验证、浏览器验收和 `pnpm validate` 全部通过。
