# 玄圭星台：问卦易读化、真实手串工作台与三语体验设计规格

**任务：** `TASK-UX-STAR-002`
**日期：** 2026-10-03
**状态：** 原书面规格及 2026-10-03 补充决策均经产品所有者确认；特别确认全新草稿不预放珠子，实施仍须逐任务登记与视觉确认

## 1. 目的与依据

面向第一次接触卦象、但希望快速选石并亲手完成水晶手串的用户，建立“看懂灵感、看清材料、顺利进入 DIY、完成一份可信设计”的连续体验。品牌保持已批准的“玄圭星台”，但高级感必须首先表现为易读、精密、真实和从容，而不是叠加术语、装饰和动效。

本规格依据产品所有者于 2026-10-03 提供的七张截图和逐项反馈、同日确认的需求拆解及中文设计提案。它修订 [原玄圭星台规格](2026-09-26-star-oracle-crystal-design.md) 中面向客户的问卦详情、结果信息层级和视觉验收方式；三钱算法、服务端幂等、权限、隐私、真实目录与既有设计权威不变。发生重叠时，本规格控制**新的客户界面呈现**，原规格仍控制未被修订的领域和安全行为。

可核对的现状证据包括：

- `/diy` 当前固定跳转到 `design-diy-private`；水晶库也引用这一固定 ID。截图中的“当前已验证身份不是这份设计的所有者”与此高度相关，实施前仍需按真实身份链路完成复现和根因确认。
- 问卦结果视图显示六爻标签、上下卦、算法版本和动爻数量；这不符合用户已经确认的“客户不需要专业细节”。
- 紧凑手串预览按珠数均分角度，并给珠子固定百分比尺寸；拥挤时没有按实际珠径与可用面积协调。
- DIY 的散珠选择态有常驻橘色外圈，工作台托盘受现有方形舞台限制；当前设计系统还规定托盘可见半径为舞台短边的 47%。
- 现有问卦内容具备中文和英文路径，但繁体中文及既有会话在切换语言后的完整本地化尚未建立；仅翻译静态按钮不足以满足“三语全页面”。

截图是当前体验的最高优先级产品证据。已有自动化曾报告对比度或视口检查通过，不等于此次用户实际看到的组合、文案、颜色和布局已达标。

## 2. 设计路线与不变边界

选择“统一视觉系统、按页面族重设计”的路线，不采用仅替换局部 CSS 的补丁，也不将实验性 3D 和强制沉浸动画升级为主路径。首页是品牌叙事场景，问卦结果是快速理解场景，DIY 是高频操作场景：共享材料、颜色、排版和控件规则，但密度按任务变化。

不可改变的产品事实：

1. 问卦提供文化观察与设计灵感，不预测确定命运，不承诺水晶功效、医疗或心理治疗效果。
2. 水晶、天然石、规格、库存、价格、货币、腕围适配、保存修订和订单快照继续由现有权威系统决定。不得为了画面捏造 SKU、材质或价格。
3. 每份私人设计仅供所有者访问；修复入口不能弱化鉴权或将他人的设计变为可读。
4. `FlatBraceletEditor` 是生产 DIY 的唯一编辑渲染路径；`BraceletPreview` 是结果页的紧凑预览。手串几何由 Bracelet Engine 控制，不能建立第二套相互矛盾的尺寸/槽位算法。
5. 不改变既有问卦随机结果、重新进入时的会话恢复、幂等键、原问题默认不持久化等行为。
6. 正在运行的内容页面、历史设计、订单和管理数据不得因为视觉或语言切换发生业务修改。

## 3. 全站视觉与内容体系

### 3.1 色彩与材质

从当前大面积相近的暖纸、浅灰与金色组合，调整为“曜石墨、冷瓷白、深墨字、旧黄铜细节”的高对比体系。候选基色为曜石墨 `#111820`、冷瓷白 `#F4F5F2`、正文深墨 `#222A2F`、辅助字 `#4B565B`、浅底上的金属文字 `#735938`。这些是设计起点，不是跳过实际截图测量的通行证：实际背景叠层、按钮、占位文案、错误状态都须分别测量 WCAG AA 对比度。

黄铜只作刻度、边线或小面积强调，不作为浅色面上的默认正文；石材青绿与紫色主要由真实产品影像呈现，不再把整页染成宝石色。深色首页与问卦氛围面使用月白文字；工作台的操作面用冷瓷白和深墨字。材质图像本身不得被色彩滤镜改变。

产品所有者补充要求全站保持克制、整洁：新生成的首页、塔罗、问卦、DIY 与 AI 入口图使用平整哑光背景和少量真实物件，不使用脏污颗粒、粗石纹、裂纹大理石、密集星线或杂乱道具；真实水晶自身的细微内含物与光泽可以保留。DIY 入口图右侧工具必须是前端有清晰小弯钩的串珠钩针，不能再出现锥子、尖刺或钻孔工具。图片不得带文字、价格或伪造商品。

2026-10-03 产品所有者对**两张入口图**作出明确选片例外：问卦入口使用其上传的旧化方孔钱、粗石与微弱星轨摄影原图（已逐字节保存为 `mystcrag-product-images-v3-refined/02-oracle-user-selected-unchanged.png`，SHA-256 `f4429ca3dbcf2f8ae33df1687d0efdbc326c4b3b628c16cfc023715ea857fc5c`）；塔罗入口使用其指定的两张清晰插画牌面、一张牌背的摄影原图（`mystcrag-product-images-v3-refined/06-tarot-user-selected-unchanged.png`，SHA-256 `65582003f5a18475690b03356f87e0b7ca5e2d64235f5e09c0fe438eeab8ce24`）。两个目录均位于 `/Users/chenyanyan/.codex/visualizations/2026/10/03/01a101bc-eb7f-7e30-8b34-68f04436d255/`。这仅放宽这两张入口装饰图的粗纹/旧化及清晰插画验收，不放宽首页、DIY 和其他图片的整洁要求。塔罗插画只作入口氛围图，不得冒充运行时授权牌组的具体牌面或抽牌结果；运行时 Tarot 卡牌仍使用现有授权资产。产品所有者指定的两张图不再被自动重绘为无纹铜钱或空白牌背。现有首页 hero 最小像素门槛仍有效，不能靠插值放大或调低常量通过。

标题可保留适合中文的书卷气；正文、价格、尺寸、导航和按钮优先使用高可读字体。卡片圆角、描边、阴影和按钮尺寸建立单一语法，不使用所有区域都套大圆角米色卡片的方式制造“高级”。

### 3.2 文字和动效

一个画面只突出一个主要动作。先写清楚“是什么、为什么推荐、下一步做什么”，再处理诗意文案；不展示内部枚举、算法标识、英文占位文案或无意义编号。正文和按钮必须在 320 px、200% 缩放与三种语言下不裁切、不互相覆盖。

动效只表达星台显现、内容到达、选珠反馈与散珠/成串状态变化。首页允许轻量视差或渐显；关键操作不依赖动效完成，`prefers-reduced-motion` 下可直接呈现稳定终态。不得使用持续粒子爆炸、强制长等待或妨碍阅读的滚动接管。

## 4. 问卦结果：从“看卦”改为“看懂设计方向”

### 4.1 信息顺序

结果页客户视图改为以下顺序，首屏优先覆盖前两项与进入选石的清楚路径：

1. **本次灵感主题：** 一句不超过两行的白话。例如“先稳住整体节奏，再留一处明亮变化”。这是界面示意，不是为任何具体卦象预先指定的结论。
2. **图形化设计线索：** 用三段相连的视觉表达“主色、节奏、点睛”，每段有可读文字；图形不以颜色为唯一信息载体。
3. **推荐石材：** 展示来自实际目录、且与本次可售方案相符的水晶/天然石图片、名称、可用规格及其视觉角色，例如“主色”“过渡”“点睛”；若库存不可用，明确标记或替换，不虚构商品。
4. **三款可选设计：** 每款显示不拥挤的真实珠串预览、自然语言的差异说明、材料重点、权威价格与明确的选中态。名称按用户语言呈现，不能输出 `BALANCED` 或 `Oracle balanced direction` 等内部字段。
5. **继续创作：** 用户选择一款后，以一个主要按钮进入自己的 DIY 设计。保存或网络失败保留当前结果、选择与可重试操作，不把用户送进空白页或他人的设计。

客户结果页完全不显示“第几爻、动爻、阴阳、上下卦、三钱算法版本”等专业信息，包括展开详情。文化与隐私解释可放在独立的“了解星台如何生成灵感”帮助内容中，用普通语言撰写；后台审计仍保存必要的结构数据。用户已经批准此隐藏边界，不能以折叠面板形式偷偷恢复专业列表。

结果摘要与三款设计应来自同一已持久化会话。界面只可从真实推荐设计和目录中提取材质示例；不能根据卦名在客户端临时编造石材。即使推荐失败，灵感主题仍可阅读，并只重试推荐，不重新起卦。三款设计始终保持真实 SKU、库存、尺寸和价格权威。

### 4.2 推荐卡片

卡片标题为短中文或对应语言的短译文，方向差异以“色彩/节奏/点睛珠”说清楚；故事正文默认最多两到三行，必要时给出真实可访问的“查看材料”入口，而不是让文字越过卡片。价格和选择操作保持可见，移动端纵向堆叠、桌面端等高比较，但不牺牲预览图尺寸去强行容纳三列。

紧凑预览必须沿用共享几何事实按实际珠径、配件占位和珠数计算显示比例；可适度缩小整体环径或珠图以留出可辨识的缝隙，但不得将所有珠子强制画成同一视觉直径。弹力线位于珠子下层，连接相邻珠心，露出的部分细而半透明，不出现一条粗白色装饰环。

## 5. DIY 入口与操作台

### 5.1 首先恢复可达性

所有“DIY 创作”入口不得依赖固定演示 ID。进入 `/diy` 时，若当前用户有历史设计，先提供清楚的“继续已有设计 / 开始新设计”选择；没有历史设计则直接进入新设计。历史设计只展示并打开当前已验证用户拥有的记录。新设计从**完全空的托盘**开始，界面不得预放一颗示例珠，也不得在用户尚未选珠时伪造符合 `DesignV1` 的已保存草稿。空托盘是前端临时工作状态；第一颗真实可售珠子被选择后，才按契约优先顺序创建当前用户的设计并取得服务端权威 ID、修订、价格和库存结果。同一次首珠意图的双击或网络重试不得创建多份设计；创建失败时保留空托盘、选珠意图及可重试路径，不虚报“已保存”。具体 API、持久化与修订策略由独立 Contract/Database/Backend 任务先冻结，Frontend 随后消费。

未登录时清楚引导登录并保留返回目标；无权限访问别人的设计时仍拒绝访问，但提供“开始自己的 DIY”恢复动作。验收需覆盖首页、导航、水晶库、问卦设计卡及个人设计入口，并用两名不同用户验证隔离。

### 5.2 桌面与移动端布局

桌面操作台保留用户认可的旧版“左侧材料库 / 中央托盘 / 右侧当前选择与佩戴适配”编排，只吸收当前版本已改善的搜索、状态、可访问性和权威数据细节，不另造大幅改变操作路径的布局。材料库只保留一套分类、搜索、筛选和商品列表；右侧只展示与当前选中珠子相关的操作、尺寸、权威总价和完成动作。中央舞台始终先满足可视与拖拽空间；必要时侧栏可收窄或折叠，而不是裁切托盘。

顶部只放次要的“保存草稿”，右侧粘性底部只放唯一主要的“完成设计”；移除页面中重复的同义主按钮。空托盘阶段这两个动作不可伪称成功，须明确提示先选择第一颗珠子；首珠持久化成功后才启用对应的服务端保存/完成流程。按钮必须具备加载、成功、失败、禁用和键盘焦点状态。保存成功需由服务端确认，不能只改变文字。

材料名一行清楚显示，规格、单价与库存移至第二层信息。横向分类或精选石材区通过露出下一项、前进箭头与触控滑动提示让用户知道还有更多；键盘也能到达后续项。列表和舞台各自滚动，不能让短视口上的“完成设计”被吞掉。

手机端保留旧版“上方托盘与散开/成串控制、下方材料库抽屉/面板”的排版和主要操作顺序，只修复当前溢出、对比度、珠材展示与触控问题；任一关键动作不需要精确命中很小的图标。所有页面在 320 px 宽度、1440×560 短桌面视口和 200% 缩放下不横向溢出、不裁切主操作。

### 5.3 托盘、散珠与成串

在空间允许的标准桌面视口，以当前截图中托盘的可见直径为基准，目标放大约 40%；短视口和手机以安全区、操作栏与托盘完整可见为上限。优先扩大中央舞台及托盘图像，而不是单独把图片放大到越过现有命中区域。可见托盘半径与舞台短边的现有 47% 关系、拖出托盘即移除的边界须同时校正；若要改变契约，必须由 Bracelet 任务先更新 `docs/BRACELET_GEOMETRY.md` 和测试。

去掉静态方形外框与托盘背后的装饰性背景板，使用干净、低干扰的中性页面底色，使托盘像一只独立实物放在操作台上；不能把整个舞台改成图片背景。拖动时可以暂时显现移除边界，静止时不显示。散珠的可见尺寸相对托盘提高，保持 6/8/10/12 mm 等规格之间的真实相对大小，并同步更新碰撞与可点击区域；不能只放大图片却留下重叠或失效命中。散珠下方有轻微、方向统一的接触阴影。橘色选择圈不再常驻；当前选择由右侧信息、克制的局部标记及 `aria-pressed` 共同表达，键盘焦点仍有高对比描边。

成串时相邻珠子要看出细微、物理可信的间隔，并由透明弹力线贯穿。视觉间距与真实材料路径、腕围适配、订单价格分离；不得为了露出线而虚增实体珠径或适配周长。散珠与成串模式、结果卡片缩图、导出 PNG 必须表达同一顺序、材质和相容的几何比例。

## 6. 首页与其他页面族

首页保留星台问卦，但恢复塔罗牌作为同等清楚的主题入口和视觉元素，不能把整页变成单一观星占卜叙事。首页图片以克制、整洁的珠宝摄影替换脏乱旧图，裁减上下无意义的浅色留白，让图像按焦点裁切并融入首屏。首屏主标题、简述和主要入口无需滚动即可识别；底部露出下一板块的一部分，并给出低干扰、可访问的向下提示。动效为短暂入场与轻量视差；不让图片加载造成布局跳动。塔罗功能关闭时不宣传不可用入口，但页面排版不留空洞。

AI 设计、Tarot（仅开启时）、水晶库、画廊、个人中心、设计详情及加载/错误/空状态沿用同一色彩、字体、按钮和状态系统，但按各自任务控制密度。知识后台同步基础对比度、字体与状态组件，不强加沉浸式星台叙事。主要导航、入口文案和现有可用功能保持真实，关闭的功能不出现空位或虚假宣传。

## 7. 简体中文、繁体中文、英文

支持 `zh-CN`、`zh-TW`、`en-US` 三种展示语言，切换菜单始终可在桌面全局页眉右侧找到，手机端在页眉或主菜单顶部可见；选项写为“简体中文 / 繁體中文 / English”，不以国旗代替语言。菜单必须真正切换页面内容，而非仅改变当前按钮或语言标签。默认语言为简体中文。切换后保留当前路由、会话 ID、已选设计、空托盘/未提交编辑与可恢复状态，且不触发重新起卦、重新选材、价格换算或保存操作。

翻译范围不是按钮子集，而是全部主要客户页面的导航、标题、说明、产品类别、表单、价格周边标签、问卦解释、设计卡名称与故事、材料名、适配说明、帮助文本、加载/错误/空状态、404 与通知；管理后台的基础操作界面也纳入文案清单，但管理数据和人工录入正文不能被静默机器改写。品牌名、SKU 和商品权威数字不翻译。语言不是币种开关，切换语言不能擅自更改 CNY/TWD 及报价。

既有目录有中文/英文名称，但并非所有动态故事都已有三语版本；Oracle 会话与推荐还绑定创建时的 locale。因此必须先由合同/内容所有者确定可验证的本地化投影或版本化文本键，使已创建会话切换语言时只改变显示文本，不改随机结果、会话身份、设计修订与权威价格。缺少译文不得静默混排两种语言或编造产品功效；上线门槛是三语的主要路径均有完整人工审校内容。URL、缓存、服务端首屏语言与用户偏好的机制在实施计划中冻结，避免闪烁和失效深链。

## 8. 状态、可访问性与验收

每个入口和重要动作至少有正常、加载、成功、错误、空数据与权限不足状态。错误应告诉用户发生了什么、哪些结果仍保留以及下一步真实可执行的动作。对比度达到 WCAG AA；触控目标至少 44×44 px；图形附文字或替代文本，不能只靠颜色；键盘、屏幕阅读器与减少动态效果的用户可完成同一主链路。

交付验收至少包括：

1. 任意 DIY 入口在当前用户会话下到达历史设计选择或可操作的空托盘工作台；无历史时直接新建空工作状态；首珠前没有虚构设计 ID 或权威价格；双用户隔离与未登录恢复通过，固定演示 ID 不再是客户主入口。
2. 不懂卦象的首次用户在结果首屏能说出本次配色/排列方向、推荐的真实石材和下一步；客户视图找不到专业爻位或算法字段。
3. 三款推荐卡在中文、繁体和英文下标题/正文/价格不溢出；珠子无不可解释的遮挡，线与间隔在标准视口可辨识。
4. 托盘在可容纳的桌面视口相对当前图约放大 40%，无静态外方框；散珠大小、阴影、碰撞和命中同步，橘圈只允许被可访问的焦点样式替代。
5. DIY 在 320×568、390×844、768×1024、1440×900、1440×560 及 200% 缩放下无页面横向溢出、无被裁切的完成动作；三种语言均复测。
6. 成串、散开、选珠、换径、拖动、删除、保存、完成、导出及刷新后的顺序、SKU、价格、库存、修订和适配数据保持一致。
7. 首页首屏没有突兀留白，下一内容入口可被发现；减少动态效果与低性能设备上不强制播放大动效。
8. 全部主要页面和状态文案通过三语人工审校与溢出检查；切换语言不重建卦象或改变商品/设计权威数据。
9. 窄测在各任务中执行；最后执行架构测试、相关跨模块/浏览器主链路和 `pnpm validate`，保留规定位置的截图与验证摘要。

## 9. 依赖与实施任务顺序

本规格只批准设计，不替代任务登记或赋予跨模块可写权限。后续计划必须按 `docs/tasks/TASK_REGISTRY.md` 注册单任务、单负责人、独立分支/工作树和精确可写路径。建议依赖顺序如下：

1. **P0 DIY 入口、历史选择与空托盘首珠创建：** Frontend 先核对现有列表/创建 API；若需新 DTO、Database 或 Backend 流程，先由相应 owner 按 Contract → Database → Backend 顺序冻结，再由 Frontend 消费。空工作状态不得违反现有 `DesignV1` 至少一珠的契约。单独做双用户、双击重放、历史选择与全入口回归。
2. **视觉与本地化基础：** UI/Frontend 统一语义 token、字体、按钮、菜单及各页面状态；翻译键与动态内容投影的合同边界先于全页面翻译。
3. **问卦结果与推荐：** AI/内容所有者提供三语、易读而合规的解释边界；Frontend 合并用户叙事、目录石材与三款结果，不改问卦引擎。
4. **手串几何与视觉：** Bracelet 所有者先确定间距/线/托盘命中的契约影响；Frontend 与 ASSET 随后更新紧凑预览、DIY 舞台、材质影像与导出表现。
5. **工作台和页面族：** Frontend 分批处理 DIY、首页、AI/Tarot、水晶库、画廊、个人中心与状态页，避免多人同时编辑锁定文件。
6. **三语收口与 QA：** 覆盖静态和动态内容、历史会话、所有视口、权限、键盘、对比度、减少动效与真实价格/库存路径；最后由 QA 执行跨模块验收。

在任何大面积实现前，先出问卦结果、DIY 桌面/手机和首页三组效果图供产品所有者确认；已生成的六张洁净素材须经素材归属、实际文件、尺寸与视觉复核后才可进入 `apps/frontend/public/**`，不能把聊天预览图路径直接当作运行时资源。此确认只决定视觉方案，不免除后续的合同、测试与任务协议。
