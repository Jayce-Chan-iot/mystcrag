## 3. Isolation properties of the gate

One command — `pnpm exec playwright test --config tests/auth-e2e/playwright.config.mts` — is one complete clean run:

- unique run id → unique database `mystcrag_auth006_<runId>_test` (name pattern asserted before any `CREATE`/`DROP`), `prisma migrate deploy` + standard seed against it;
- unique port plan (18443/18444/18445/18446/18447/18450/18460/18461 + 18451/18470 for negative spawns), asserted free before start and verified released at teardown;
- run-scoped build checkout: `apps/backend` and `apps/frontend` are copied into `output/playwright/auth-006/<runId>/work/apps/` and every build and start runs INSIDE that copy — the developer workspace's `.next`/`dist` is never read, and **no build output is ever reused between runs**;
- self-signed multi-SAN TLS certs for `synthetic.auth006.internal`, `app.mystcrag.auth006.internal`, `api.mystcrag.auth006.internal`; in-process synthetic OIDC provider (HTTPS issuer, HTTP admin control plane); browser CONNECT relay and `node:net` `connect()` preload to remap the port-443 issuer; TLS reverse proxies for the production HTTPS topology;
- backend and frontend built from **unmodified sources** by the unmodified build pipelines and started as production runtimes (`next start`, `node dist/index.js`);
- a fixture-level regression assertion enforces the production config contract `MYSTCRAG_AUTH_CALLBACK_URL === MYSTCRAG_APP_ORIGIN + '/auth/callback'` before any process starts, and readiness requires the production-topology frontend's auth configuration to actually resolve (`/auth/session` answers authenticated JSON) — a Proxy fail-closed page can never be mistaken for "ready";
- all secrets (client secret, session secret, admin token) are generated in memory per run and never appear on any command line, in any log, or in any artifact; local runs keep them only in process memory. In CI they are exported through GitHub's `$GITHUB_ENV`, which the runner materialises as a temporary environment file on the build machine for the job's duration — each value is registered with `add-mask` the instant it is created so it can never surface in logs; the file itself is a job-lifetime runner artifact and is never part of any published evidence;
- teardown stops only processes it started — live `ChildProcess` handles are stopped directly (their command signature was captured at spawn), pids recovered from run-state.json are verified against the CURRENT command line AND the run-scoped working directory before any signal, and every spec-spawned extra child (negative-config spawns and H9's stand-ins) is additionally tracked in a durable run-scoped ownership record so a crashed worker can never orphan one — teardown recovers each record, re-verifies the command signature AND the run-scoped cwd on the live pid, and only then signals — verifies every owned port was released, drops and verifies gone its own database, redacts credential-bearing headers from retained trace archives, and scans every retained artifact for the run's secrets plus token/cookie leakage patterns (including decompressed trace content). Any hit fails the run. A child whose durable registration fails is reclaimed (SIGTERM → SIGKILL, exit awaited) before the failure surfaces, so a failed registration never leaks a live process or a bound port.
- a failed setup still tears the stack down, and when that cleanup fails too, BOTH errors propagate as one `AggregateError` (repair #3 below) — leftover resources can never hide behind the setup error.

Nothing from a developer machine is reused: no dev server, no dev database, no shared `.next`, no pre-seeded browser state, no production Auth0 tenant. Test order independence is enforced by serial execution (`workers: 1`, `retries: 0`) with per-test synthetic identities.

Two harness defects were found and fixed while closing this round, neither weakening any assertion:

1. **C4 prefetch race** — C4 was the only logout test without `suppressRouterPrefetch`/`networkidle`: an in-flight router prefetch issued after the logout POST could re-roll the SDK session and resurrect `authenticated`, surfacing as a flake under a busier 49-test run. C4 now applies the same prefetch suppression every other cookie-sensitive C test already used (aborting prefetch never weakens assertions — the assertions still cover every request the test itself makes).
2. **I2 topology binding** — the first I2 draft drove mutations through `page.request` (a Node-side APIRequestContext) which cannot resolve the browser-only synthetic DNS; the final I2 drives every request from the real page over the real TLS topology (see I2 evidence below).

Two harness defects were found and fixed in an earlier round while closing the H3 regression, both in the relay's tunnel gate (never in allowlist semantics):

1. **Partial-record parsing** — a ClientHello split across TCP segments was parsed as "not a hello" and destroyed a legitimate tunnel; the gate now buffers until the 5-byte record header declares the record complete.
2. **Listener-gap race** — tunnel bytes pipelined right behind the CONNECT head could fire a `data` event between head consumption and gate arming, with no listener registered (flowing mode silently discards them). The relay now `pause()`s the socket the moment the head is parsed and `resume()`s it only after the SNI gate is armed, so no byte can ever be lost in that gap. H3 exercises exactly this pipelining shape, which is why the real-browser flow (always waits for the 200) never exposed it.

- `tests/auth-e2e/package.json` does not exist in the candidate (ES modules are declared per-file via `.mts`/`.mjs`; no directory-local manifest).
- Retained run evidence lives only under `output/playwright/auth-006/<runId>/` (git-ignored): stack logs, run-state, failure-only traces/screenshots (none — all green), per-run TLS material and per-run build checkout.
- The CI artifact contract: ONLY the sanitized, explicitly allowlisted directory `output/playwright/auth-006-sanitized/` is ever uploaded (`actions/upload-artifact@v4`, failure-only, 7-day retention), and the upload step is additionally gated on the sanitizer step's own success. The sanitizer never copies TLS material (the whole `tls/` directory, `*.pem`, `*.key`, the provider private key by basename), never copies the run-scoped build tree (`work/`), considers only allowlisted extensions (`.log .json .txt .md .zip`) — binary image types such as `.png` are NOT allowlisted and are NEVER uploaded unscanned, because their content cannot be reliably proven free of credential material (screenshots inside zip trace archives remain covered, because every zip entry is scanned) — and never reads or copies a symbolic link: enforced twice, at collection (dirent type) and at open time (`O_NOFOLLOW`, so a mid-run symlink swap fails closed with ELOOP, never reading the target). Every file's NAME is scanned for credential material FIRST — before any directory, basename or extension decision — so a secret-bearing path is a violation that publishes nothing, never a mere "excluded" summary entry. Every file is opened EXACTLY ONCE with `O_NOFOLLOW | O_NONBLOCK`, `fstat`-verified as a regular file on that same descriptor (also fail-closing on FIFOs), proven — after the open, before any byte is read — to live inside the canonical source root (Linux: `/proc/self/fd/<fd>` must resolve inside the root; every platform: each ancestor lstat-verified as a real directory and the final component's dev+ino identity must equal the descriptor's fstat identity), and the SAME bytes read from that ONE descriptor are both scanned AND written to staging — no second open can slip different content between scan and copy. Zip entries are scanned from those same in-memory bytes on their RAW bytes (literal secrets byte-wise; patterns on both the UTF-8 and Latin-1 decodings) — a NUL byte or binary content never skips the scan. Traversal failures are fatal (a failed `readdir` is never an empty directory; an unreadable file is a recorded violation). The PUBLISHED `sanitize-summary.json` is path-free (opaque references only), run secrets are read ONLY from the named environment variables — never from the command line — and the CLI's stdout/stderr print only sanitized categories, counts and opaque references, never a hit's path, entry name, or secret value. The sanitized tree is built in a staging directory and published with one atomic rename only after a zero-violation scan; a violation, a sanitizer error, or an unreadable source publishes nothing at all, and the CI upload gate skips the upload. No raw trace, TLS private key, or credential-bearing file can reach the upload directory; on passing runs (like both clean rounds here) nothing is uploaded at all.

## 9. Residual risks and current limitations

1. **No real external Auth0 tenant is exercised.** The OIDC counterparty is the in-process synthetic provider (correct discovery document, JWKS-backed signed tokens, PKCE, code exchange, refresh). The SDK, validators, and every production code path under test are the real ones; only the wire counterparty is synthetic. A real-tenant smoke run remains future work outside this task's scope.
2. **CI has not yet executed on a GitHub runner.** The workflow (including the double-gated upload, the `add-mask`-ed `$GITHUB_ENV` secret export, and the environment-variable-only sanitizer interface) is verified by the static H8 regression, the H4c real-CLI regression, and by inspection; `steps.<id>.outcome` semantics follow documented GitHub Actions behavior. In CI the secrets live in GitHub's `$GITHUB_ENV` runner file for the job's lifetime (masked in all logs); local runs keep them in process memory only.
3. The run-scoped cwd verification of recovered pids was exercised locally on macOS (`lsof`); the Linux branch (`/proc/<pid>/cwd` readlink) will first execute on the GitHub runner.
4. Local PostgreSQL is 17.10 while CI pins pgvector/pgvector:pg16 — migrations passed on both major versions' required surface (17 locally, 16 via the earlier repository baselines).
5. The backend production-bundle runtime restorations (`NODE_PATH` to pnpm's hoisted store for `require.resolve("jquery")`, and the `xhr-sync-worker.js` symlink) compensate a pre-existing main gap documented in `tests/auth-e2e/RUNBOOK.md`; they are harness-side only and touch no tracked file.
